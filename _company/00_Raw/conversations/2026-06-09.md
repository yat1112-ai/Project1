# 🎮 모바일 RPG 트렌드 분석 보고서: 스타일리시 액션과 깊은 시스템의 결합 (초안)

## Ⅰ. 개요 및 목표 설정
최근 성공작들은 단순한 스토리 전달이나 전투 시뮬레이션에 머무르지 않고, **'캐릭터가 곧 게임 플레이의 핵심이자 매력'**이며, 이 캐릭터들이 고난도의 상호작용을 통해 성장하는 경험을 제공합니다.

우리가 지향해야 할 목표는 다음과 같습니다:
1.  **액션 스타일리시함 (DMC 요소):** 높은 기동성, 화려한 연계기, 플레이어의 숙련도가 곧 보상으로 돌아오는 **'조작의 재미(Feel)'**.
2.  **시스템 깊이와 수집 욕구 (Nikke/Gacha 요소):** 캐릭터 육성, 장비 파밍, 스토리 분기 등 지속적인 동기 부여가 필요한 **'파밍 루프(Loop)'**.

## Ⅲ. 핵심 사용자 경험 (UX) 요소 분석: 공통점 도출

이 세 게임은 표면적으로는 장르가 다르지만, 플레이어가 지속적으로 몰입하게 만드는 **공통된 심리적 루프**를 공유하고 있습니다.

### 1. Ownership & Identity (소유와 정체성)
*   **요소:** 단순히 캐릭터를 얻는 것(Gacha)을 넘어, '나만의 조합'이라는 주도권을 부여합니다.
*   **실현 방법:** 고유한 서브 스토리라인, 직업군 시스템, 혹은 상호작용하는 파티원 간의 관계성(Bonds). (ex: 아크 나이츠에서 특정 캐릭터가 가진 *역할*을 발견하고 그에 맞춰 팀을 짜는 것)
*   **액션 접목:** "내가 이 조합으로 이 스테이지를 클리어했다"라는 **'전략적 성취감'**을 시각적인 연출로 폭발시켜 보여줘야 합니다.

### 2. The Compulsion Loop (강박적 순환 고리)
*   **요소:** 보상(Reward) → 성장(Progression) → 다음 목표 설정(Goal Setting)의 무한 루프입니다.
*   **구체화:** **[약점 발견]** → **[캐릭터/장비 파밍]** → **[다음 콘텐츠 도전]** → **[더 높은 목표 설정]**. 이 사이클이 끊임없이 돌아가게 만들어야 합니다.
*   **액션 접목:** 단순한 레벨업보다, '신규 캐릭터를 얻어 그 캐릭터의 고유 스킬을 배우고 이를 활용해 기존 클리어 불가 콘텐츠에 도전하는' 방식이 강력합니다.

### 3. Visual Spectacle (시각적 장관)
*   **요소:** 액션의 결과(Damage Number)나 스킬 사용 자체가 **예술 작품처럼 느껴지게 만듭니다.**
*   **DMC 연계점:** 화려한 필살기, 스타일리시한 패링/회피 효과 등 캐릭터의 *개성*을 시각적으로 과장해야 합니다. 이는 턴제 전투라도 충분히 구현 가능합니다.

## Ⅳ. 수익화 포인트 분석 (Monetization Hooks)

| 전략적 목표 | 구체적인 수익 모델 | 유저가 느끼는 감정 |
| :--- | :--- | :--- |
| **1. 파밍 시간 단축** | *에너지 회복/시간 가속* (핵심 과금 포인트). 고난도 콘텐츠 진입 장벽 설정. | "빨리 경험하고 싶다." (Time Sink) |
| **2. 최적화된 조합 완성** | *고성능 장비 제작 재료* 또는 *특정 캐릭터의 코어 강화재*. | "내 파티를 완벽하게 만들고 싶다." (Collection/Optimization) |
| **3. 스토리 경험 확장** | *미공개 에피소드 챕터 잠금 해제*, 혹은 *캐릭터 고유의 '특별한' 스킨/모드*. | "이들의 이야기가 궁금하다." (Narrative Desire) |

## III. 타이포그래피 가이드라인 (Typography Guidelines)

폰트는 시스템적이고 기능적인 느낌을 주면서도 시각적 임팩트를 놓치지 않아야 합니다.

1.  **헤드라인/로고 타입 (Impact):**
    *   **추천 스타일:** Strong Geometric Sans-Serif (예: *Montserrat Black, Orbitron 계열*)
    *   **사용 목적:** 게임 타이틀, 주요 챕터 제목, 핵심 메시지 등 시선을 강하게 사로잡아야 하는 부분.
    *   **처리 지침:** 글자 자체에 미세한 **디지털 노이즈(Digital Noise)** 또는 **글리치 효과(Glitch Effect)**를 적용하여 '시스템의 산물'이라는 느낌을 강화합니다.

2.  **본문/UI 타입 (Readability):**
    *   **추천 스타일:** Clean, Minimal Sans-Serif (예: *Roboto, Inter 계열*)
    *   **사용 목적:** 대사창, 능력치 수치, 메뉴 옵션 등 사용자가 가장 오래 읽어야 하는 모든 텍스트.
    *   **처리 지침:** 높은 가독성을 최우선으로 하되, 색상은 항상 **네온 시안(Neon Cyan)**을 기본값으로 사용하여 '정보가 빛나는' 느낌을 유지합니다.

## 📐 Part 2. 와이어프레임 & 컴포넌트 명세 (The Blueprint)

각 화면의 구조와 필수 요소들을 정의합니다. (※ 실제 프로토타입에서는 이 구조 위에 애니메이션을 입힙니다.)

### A. [BOOT] 시스템 접속 화면 (Login Screen)
*   **배경:** 미니멀한 블랙 배경에 느리게 움직이는 데이터 스트림(Particle Effect)이 흐름.
*   **핵심 컴포넌트:**
    1.  **[SYSTEM LOG]:** 상단 중앙에 텍스트가 타이핑되는 듯한 애니메이션 (e.g., `CONNECTING TO ECHOS... OK`).
    2.  **[USER INPUT BOX]:** ID/PW 입력 필드. 포커스 시 네온 시안 테두리 깜빡임 효과 필수.
    3.  **[ACCESS BUTTON]:** "시스템 접속" 버튼. 마우스 오버 시, 데이터 왜곡(Glitch) 애니메이션이 잠시 발생하며 활성화됨.

### B. [MAIN] 아카이브 메인 허브 (Home Screen)
*   **레이아웃:** 3분할 구조 (좌: 캐릭터 상태 패널 / 중앙: 주요 스토리라인/퀘스트 로그 / 우: 시스템 알림 및 자원 현황).
*   **핵심 컴포넌트:**
    1.  **[PROFILE DATA]:** 플레이어 이름, 레벨 등은 고전적인 폰트로 처리하되, '데이터 버전'과 같은 사이버펑크 요소를 추가.
    2.  **[STORY ENTRY PANEL]:** 메인 스토리를 나타내는 가장 큰 카드형 컴포넌트. (클릭 유도 지점)
    3.  **[NAVIGATIONAL BUTTONS]:** '스토리 아카이브', '자원 매매소(Shop)', '설정' 등은 버튼이 아닌, **데이터 포트를 연결하는 듯한 아이콘 형태**로 디자인하여 시스템의 일부처럼 보이게 합니다.

### C. [SUB] 스토리 아카이브 (Story/Character Select)
*   **레이아웃:** 컨텐츠 중심형. 왼쪽에는 캐릭터 데이터 카드(Data Card), 오른쪽은 서사 흐름도(Flowchart) 배치.
*   **핵심 컴포넌트:**
    1.  **[CHARACTER DATA CARD]:** 단순히 이미지를 보여주는 것이 아니라, '파일 ID: XXXX'와 같은 식별자와 함께 **데이터 왜곡 필터가 적용된 썸네일**을 사용합니다.
    2.  **[RELATIONSHIP MAP]:** 캐릭터 간의 관계를 일반적인 선이 아닌, **연결되는 네온 전선(Wire)**으로 시각화하여 '시스템적 연결' 느낌을 극대화합니다.
    3.  **전환 효과 (Crucial):** 이 화면에서 특정 캐릭터를 선택하면, 배경이 일시적으로 **데이터 글리치 노이즈(Glitch Noise)**로 뒤덮이고, 해당 캐릭터의 데이터 파일명과 함께 새로운 씬으로 진입하는 애니메이션을 적용해야 합니다.

### D. [SUB] 상점 인터페이스 (Resource Hub)

## 3. 핵심 상호작용 로직 (Mockup Code Logic - React TypeScript)

핵심은 `GlobalStateContext`를 통해 현재 시스템의 상태(`SystemStatus`)와 데이터를 관리하는 것입니다.

### A. Global State Context (`GlobalStateContext.tsx`)

이 곳에서 모든 플로우 제어 코드가 정의됩니다.

```tsx
// 🚨 중요: 이 함수들이 '클릭 이벤트'에 바인딩되어야 함
const useSystemStatus = () => {
  const [status, setStatus] = useState<SystemStatus>('BOOTING'); // 초기 상태는 부팅 중
  const [data, setData] = useState<{ user: UserProfile; archiveData: any[] }>({ /* ... */ });

  // 1. BOOT -> MAIN (인증 성공) 플로우
  const handleLoginSuccess = useCallback((user: UserProfile) => {
    setData(prev => ({ ...prev, user }));
    setStatus('MAIN_HUB'); // 상태 변경을 통해 MainHubScreen이 렌더링됨
    // 여기에 "데이터 아카이브 인터페이스"의 부팅 사운드/글리치 효과 트리거 로직 추가
  }, []);

  // 2. MAIN -> SUB (스토리 진입) 플로우
  const enterStoryArchive = useCallback((characterId: string) => {
    setStatus('STORY_VIEW'); // 상태를 Story View로 변경
    // 전역적으로 아카이브 데이터 로딩을 트리거하고, 화면 전환 애니메이션 시작
  }, []);

  // 3. SUB -> MAIN (뒤로 가기) 플로우
  const exitView = useCallback(() => {
    setStatus('MAIN_HUB'); // 이전 상태로 돌아감
  }, []);

  return { status, data, handleLoginSuccess, enterStoryArchive, exitView };
};
```

### B. 메인 라우터 (`SystemRouter.tsx`)

이 컴포넌트는 오직 `status` 값에 의해서만 자식 컴포넌트를 렌더링합니다.

```tsx
// Next.js 페이지의 핵심 로직 역할을 수행하는 컴포넌트라고 가정
const SystemRouter: React.FC = () => {
  const { status } = useSystemStatus();
  let CurrentScreenComponent;

  switch (status) {
    case 'BOOTING':
      CurrentScreenComponent = <TransitionWrapper Effect="booting" />; // 부팅 효과 필수
      break;
    case 'MAIN_HUB':
      CurrentScreenComponent = <MainHubScreen onEnterStory={useSystemStatus().enterStoryArchive} />;
      break;
    case 'STORY_VIEW':
      // Story View는 아카이브 데이터에 따라 내용이 달라져야 함 (조건부 렌더링)
      const { data } = useSystemStatus();
      CurrentScreenComponent = <ArchiveContent characterId={data.user?.activeCharacter} onBack={useSystemStatus().exitView} />;
      break;
    default:
      CurrentScreenComponent = <div className="text-red-500">Error: Unknown System State</div>;
  }

  return (
    <main className="relative w-full h-screen overflow-hidden">
      {/* 모든 화면은 이 TransitionWrapper 안에서 렌더링되어야 함 */}
      <CurrentScreenComponent />
    </main>
  );
};
```

import React, { createContext, useContext, useState, useCallback } from 'react';
import { GameState, StateArgs, Action } from '../types/gameStateTypes';

/**
 * @interface StateMachineContextType
 * 모든 상태 관리 로직을 캡슐화한 Context의 타입 정의입니다.
 */
export interface StateMachineContextType {
    currentState: GameState;
    setState: (action: Action, args?: Record<string, any>) => Promise<void>; // 핵심 함수
    history: GameState[]; // 상태 기록 추적
}

/**
 * @context StateMachineContext
 * 전역적으로 사용되는 상태 기계 Context입니다. 이 컴포넌트를 감싸는 모든 하위 컴포넌트는 이 컨텍스트를 통해 상태 변화에 접근합니다.
 */
export const StateMachineContext = createContext<StateMachineContextType | undefined>(undefined);

/**
 * @hook useStateMachine
 * 애플리케이션 전체에서 사용 가능한 커스텀 훅입니다.
 * <p>주의: 실제 로직은 이 훅 내부의 `setState` 함수에 구현됩니다.</p>
 */
export const useStateMachine = () => {
    const context = useContext(StateMachineContext);
    if (!context) {
        throw new Error('useStateMachine must be used within a StateMachineProvider');
    }
    return context;
};

/**
 * @component StateMachineProvider
 * 애플리케이션의 최상단에서 상태 기계를 초기화하고 관리하는 Provider입니다.
 */
export const StateMachineProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
    // 실제로는 여기서 전역 리덕스/훅을 사용하지만, 시뮬레이션을 위해 useState로 구현합니다.
    const [currentState, setCurrentState] = useState<GameState>('BOOT');
    const [history, setHistory] = useState<GameState>(['BOOT']);

    /**
     * @function setState
     * 상태 기계를 변경하는 핵심 함수입니다.
     * 이 함수는 '비동기'로 설계되어 데이터 로딩이나 복잡한 초기화 과정을 시뮬레이션할 수 있게 합니다.
     */
    const setState = useCallback(async (action: Action, args?: Record<string, any>): Promise<void> => {
        console.log(`\n⚙️ [STATE MACHINE]: ${currentState} -> ? (${action})`);

        // 1. 상태 전이 유효성 검사 및 로직 실행 (여기에 복잡한 비즈니스 로직을 구현해야 함)
        let nextState: GameState | null = null;

        switch (currentState) {
            case 'BOOT':
                if (action === 'INIT') {
                    nextState = 'MAIN_HUB'; // 부팅 완료 -> 메인 허브 진입
                } else {
                    throw new Error('Invalid action from BOOT state.');
                }
                break;

            case 'MAIN_HUB':
                if (action === 'SELECT_CHARACTER') {
                    // args에서 캐릭터 ID를 받아서 검증하고 다음 상태로 이동합니다.
                    nextState = 'CHARACTER_SELECT'; 
                } else if (action === 'OPEN_SHOP') {
                    nextState = 'SHOPPING';
                } else if (action === 'CHANGE_SETTINGS') {
                    nextState = 'SETTINGS';
                } else {
                    throw new Error('Invalid action from MAIN_HUB state.');
                }
                break;

            case 'CHARACTER_SELECT':
                if (action === 'START_STORY') {
                     // 캐릭터 선택이 확정되면 스토리로 진입합니다.
                    nextState = 'STORY_NARRATIVE'; 
                } else {
                    throw new Error('Invalid action from CHARACTER_SELECT state.');
                }
                break;

            case 'STORY_NARRATIVE':
                 // 스토리 엔딩, 분기점 등 로직에 따라 다음 상태를 결정합니다.
                 if (action === 'INIT') { // 예시: 스토리 챕터 완료 후 돌아가기
                    nextState = 'MAIN_HUB';
                 } else {
                     throw new Error('Invalid action from STORY_NARRATIVE state.');
                 }
                break;

            // ... 나머지 상태 케이스 추가 (SHOPPING, SETTINGS 등)
            default:
                console.error(`[ERROR] Unknown state or transition attempted.`);
                nextState = null;
        }

        if (!nextState) {
             throw new Error("Transition failed: State logic could not determine a valid next state.");
        }
        
        // 2. 상태 업데이트 (Atomic Update)
        setCurrentState(nextState);
        setHistory(prev => [...prev, nextState]);

        console.log(`✅ [STATE MACHINE]: Successfully transitioned to ${nextState}.`);
        return Promise.resolve(); // 성공적으로 완료되었다고 가정합니다.
    }, [currentState]);


    const contextValue: StateMachineContextType = {
        currentState,
        setState,
        history,
    };

    return (
        <StateMachineContext.Provider value={contextValue}>
            {children}
        </StateMachineContext.Provider>
    );
};
